# BioSyncd Phase 2 — Release Plan

## The timing question, answered

Start building Phase 2 now. Put it on sale roughly 60 to 90 days after the Phase 1 books go live. Both halves of that sentence matter.

Here is the math that forces it.

Phase 1 tells every reader that the advanced modules "will be waiting" for anyone who passes the compatibility check. That is a promise with a clock on it. A reader who buys on launch day runs the three-week install calendar, then the thirty-day stability phase. The earliest anyone can legitimately qualify for Phase 2 is about day 51 after they start — call it day 60 once you account for reading time and real life. If the first wave of operators passes the checklist and there is nothing to buy, the trust the whole gate is built on breaks. The "earn it" framing only works if the reward exists when it is earned.

The launch blueprint points at the same window from the revenue side. Book sales fall off a cliff at 30, 60, and 90 days as launch buzz fades and the Amazon algorithm resets. The plan already calls for a back-end offer to catch that drop. Phase 2 is that offer. It lands in front of the most committed buyers at the exact moment they are qualified, primed, and looking for what comes next.

Then there is production reality. Phase 1 went from finished manuscript to ordered proofs in about four months. Phase 2 has the same road ahead of it, plus the writing itself. If the manuscript is not moving before Phase 1 launches, the sale date slips past the window when the first cohort qualifies, and the promise in the book goes unmet.

## What "prepare now" means

- Lock the outline. Phase 2's scope is not open — the Phase 1 book already told readers what is in it. See `advanced-bios-outline.md`. Anything added beyond that is a bonus; anything promised and missing is a problem.
- Draft in module order: Breath Suite first, then Thermal Cycling, then Speed-Patching, then Pattern Mapping. The first two stand alone and can be written without any app decisions.
- Decide the app question early. Two of the five promised components (predictive patching and personalized code libraries) assume the app exists. The outline proposes a paper-first version of both so the book delivers the full promise on its own, with the app as a later unlock rather than a dependency.
- Build the Phase 2 workbook in parallel with the manuscript, not after it. That sequencing cost time on Phase 1.
- Keep the physical design continuous with Phase 1 — same trim, same spine system, same cover language. The two books should look like versions of the same software, because that is the brand.

## What waits

- No public announcement, no cover reveal, no date until Phase 1 launch has actually executed. Launch attention stays on Phase 1.
- No marketing spend on Phase 2. The buyers are already inside Phase 1; the book itself is the funnel.
- No Phase 3 work beyond a one-page concept note. It exists in the Phase 2 back matter as a teaser and nothing more.

## Working schedule

Everything keys off L, the Phase 1 on-sale date.

| Milestone | Target |
|---|---|
| Phase 2 outline locked | now |
| Modules 1–2 drafted (Breath Suite, Thermal Cycling) | L minus 4 weeks |
| Modules 3–4 drafted (Speed-Patching, Pattern Mapping) | L |
| Full manuscript complete, edit pass done | L + 3 weeks |
| Layout, cover, workbook files final | L + 6 weeks |
| Proofs ordered | L + 7 weeks |
| Phase 2 on sale | L + 60 to 90 days |

If Phase 1 launch moves, everything here moves with it. The one fixed rule: Phase 2 must be purchasable before the first honest operator passes the compatibility check.

## Price and gate mechanics (to decide)

The book says Phase 2 "is purchased separately and is only available to operators who have completed the compatibility check." Options for honoring the gate without building software:

1. Honor system with teeth — the checkout page presents the seven-point compatibility check as a self-certification, same language as the book. Cheap, on-brand, and consistent with the Operator Oath.
2. Code-in-book — the Phase 1 book's stability tracker page carries a phrase or code that unlocks the Phase 2 order page. Slightly stronger gate, slightly more friction.
3. Open sale, gated framing — anyone can buy, but the book's own front matter re-runs the compatibility check and tells unqualified readers to stop and go back. Maximizes revenue, softest gate.

Recommendation: option 1 now, option 2 if the gate gets abused. The gate is positioning, not security.
